# BitGarth 0.2.2

## Highlights

- Bitcoin accounts whose transaction history was left incomplete repair
  themselves: every installation re-checks its Bitcoin accounts once after this
  upgrade and downloads the history that is missing.
- A historical balance is only presented as final when the transactions behind
  it are complete. Balances that were worked backwards from the current balance
  could be wrong; they no longer appear as if they were certain.
- Balance-only accounts now show the current balance and when it was last
  checked, instead of historical balances that need a full transaction history.

## New

- Balance-only accounts show "Current balance as of {time}" at the top of the
  transactions page.
- An account with missing transaction history now says roughly how many
  transactions are unsynced.
- The current and latest version numbers on the Settings page link to their
  release notes.

## Fixed

- A Bitcoin account tracking an xpub now spreads its history download across the
  account's addresses, newest transactions first, instead of letting the older
  transactions of one address use up the whole allowance.
- Opening and closing balances calculated back from the current balance could be
  wrong whenever a newer transaction was missing. A balance is now taken from
  complete history or shown as "Not available".
- Balance assertions in hledger exports now set the account balance directly.
  They were written as a difference from the previous assertion, which came out
  wrong when transactions fell between the two.
- A page that loads several things at once no longer mixes data from before and
  after a background update, so everything on screen comes from the same moment.
