# BitGarth 0.5.0

## Highlights

- Manage wallets and accounts, start a sync, and run a *Holdings Report* from
  the command line. Add `--json` to use the results in a script.
- Look up what an asset was worth on a particular day. The new *Prices* page
  shows prices for assets in your wallets, in your reporting currency. Filter
  by date or source to find a price you entered or a daily CoinGecko quote.
- See what each transaction was worth on the day it happened. The range
  summary shows your opening balance, receipts, spending, fees, and closing
  balance. Fiat totals for receipts, spending, and fees appear when every
  transaction counted in the summary has a price.

## New

- Choose full or read-only access when pairing the CLI. You can lower an
  existing full-access client's permission under *Settings → Paired Clients*.
- Transfer wallets, accounts, addresses, and manual balances between installs
  with a password-encrypted ZIP from the CLI. Transfers require full access
  and leave settings, saved API keys, and subscriptions out of the archive.
- Daily CoinGecko prices keep updating while you're signed out if anyone on
  your instance has price syncing enabled. Your own setting controls whether
  you see CoinGecko prices. On Free, you can browse the last nine months of
  CoinGecko prices and the full history of prices you entered yourself.
- Search for a timezone by city or region in *Settings*, or use your browser's
  timezone.
- See how many transaction entries your accounting export contains before you
  download it.
- Browse previously loaded plan descriptions when BitGarth's servers are
  unavailable. Checkout resumes once current prices are available.
- Verify a downloaded CLI or web archive against the release workflow, tag,
  and source commit using the commands on the GitHub release page.

## Fixed

- Bitcoin reports now leave the closing balance unknown when history doesn't
  cover the end of the selected day. Where available, the report shows the
  last confirmed amount and sync time separately so you can see what was known.
- The *Holdings Report* explains whether a missing value needs more transaction
  history or a price for that day, and keeps opening and closing totals visible
  on small screens even when a value is unknown.
- Signing in or registering now opens *Wallets* reliably. A failed sign-in
  shows a support code when diagnostic details are needed.
- Wallet rows and report prices fit on narrow screens. Small balances and
  rounded report prices are easier to read in your selected currency.
- On phones, the bottom navigation now takes you directly to *Wallets*,
  *Reports*, *Prices*, and *Settings*.
- Copy buttons now work more reliably in Safari and Firefox and confirm a
  copy only after the browser succeeds.
- The encrypted wallet database now uses a version of SQLite that includes
  security fixes.

## Notes

- Upgrade your server before pairing a new CLI profile or using the new
  commands. Existing balance-only profiles can still run `bitgarth balance`.
  The `bs` and `balancesheet` aliases still work.
- Update scripts that use `bitgarth pair` or `bitgarth login` to use
  `bitgarth auth login`. New pairings request full access by default. Add
  `--read-only` to request read-only access.
- Profile commands have moved. Use `bitgarth auth status` to list profiles,
  `bitgarth auth rename OLD NEW` to rename one, and
  `bitgarth auth logout --profile NAME --local-only` to remove it locally.
  Omit `--local-only` to revoke the key on the server as well.
- The account mode previously called *Transaction syncing* is now called
  *Full history*.
