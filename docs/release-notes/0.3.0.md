# BitGarth 0.3.0

## Highlights

- BitGarth's source code is now published. Every release is built from a public
  commit you can read, audit, and build yourself.
- A new `bitgarth` command-line client reads your wallet balances from a
  terminal. You pair it once in your browser. In this release it shows
  balances; later releases will give it more to do.
- A Bitcoin account that reached its per-account transaction limit no longer
  shows "Syncing" forever.

## New

- The `bitgarth` command-line client prints a balance sheet of your wallets. Run
  `bitgarth pair`, open the approval link it prints, approve it in BitGarth, then
  run `bitgarth balancesheet` (short: `bs`).
- Ready-to-run downloads of the CLI for Linux, macOS on Apple Silicon, and
  Windows are attached to each release, with checksums. You can also build it
  from source.
- The CLI keeps a profile per BitGarth you connect to, so one machine can
  reach several installs. Manage them with `bitgarth profile list`,
  `bitgarth profile rename`, and `bitgarth profile remove`.
- **Settings → Paired Clients** lists everything you have paired, with when it
  was created, when it expires, and when it was last used. Revoking one cuts off
  its access immediately, without affecting your password or your other paired
  clients.
- The CLI requires HTTPS by default, and will not send its credentials over
  plain HTTP unless you allow that explicitly.

## Fixed

- A Bitcoin account that hit its per-account transaction limit stayed marked
  "Syncing" indefinitely and kept re-running sync in the background. It now
  settles once the permitted history has downloaded, and the history still
  waiting is picked up later if that limit is raised.
- Refreshing your wallets or checking for a new version could break the page
  until you reloaded it.

## Notes

- BitGarth is published under the Functional Source License 1.1
  (FSL-1.1-ALv2). Each release additionally becomes available under the Apache
  License 2.0 on its second anniversary.
- BitGarth's internal web addresses moved from `/api/v1/` to `/_app/`, and its
  health check is now `/health`. If you self-host behind a reverse proxy that
  filters or rewrites paths, allow `/_app/` and `/health`. Hosted, Umbrel, and
  plain Docker installs need no change.
