# BitGarth 0.2.1

## Highlights

- Various transaction history fixes: accounts that were missing older
  transactions are found and completed automatically.
- Synced Ethereum transactions could show the wrong amount when a
  transaction moved ETH internally more than once. This is fixed, and
  history you already synced repairs itself automatically.

## Fixed

- An account syncing its transaction history for the first time could miss
  its older transactions if its balances had already been tracked for a
  while. The full history now downloads, and every installation re-checks
  its accounts and finishes any history that was left incomplete.
- Ethereum transactions that move ETH internally more than once — common
  with contract interactions — could record only one of those movements, so
  amounts and balances came out wrong. All movements are now kept, and
  existing history is rebuilt from data BitGarth already has.
- An account whose transaction history is only partly downloaded now shows
  "Not available" as its opening balance instead of a number computed from
  the incomplete history.
- The opening balance no longer flips to "Not available" when you view a
  period with no transactions on an account that does have history.
- An account whose balance had not come through yet now fetches it on the
  next sync, instead of waiting for new activity on the network.
- Pressing Sync now reports what the sync actually did, even when tidy-up
  work afterwards fails.
